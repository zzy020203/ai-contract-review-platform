## 1. 引言

### 1.1 编写目的

本文档面向企业智能合同审查平台（以下简称"本平台"），对系统的业务背景、用户角色、功能需求、非功能需求、业务流程与验收标准进行完整定义，作为后续技术设计、开发实现、测试验收与私有化交付的依据。

### 1.2 项目背景

企业法务与合规人员在日常工作中需要对大量采购、销售、合作、劳动等合同进行审查。传统人工审查模式存在明显瓶颈：

1. **审查周期长**：单份合同动辄数十页，逐条比对耗时，业务高峰期合同积压严重。
2. **审查标准不一**：不同法务人员的经验与尺度不同，同类风险的认定口径不一致。
3. **基础工作耗时**：大量时间消耗在条款定位、文字比对等机械劳动上，高价值判断被挤压。
4. **过程留痕缺失**：审查意见多通过邮件、批注流转，修改过程不可追溯，责任边界模糊。
5. **关键条款漏检风险高**：疲劳与经验盲区导致管辖、违约责任、知识产权等关键条款漏审，带来法律风险。

随着大语言模型（LLM）、RAG 检索增强与多 Agent 编排技术的成熟，将"规则可配置、AI 初审 + 人工复核、全程留痕"的智能审查能力引入法务场景已具备工程可行性。本平台即在此背景下立项。

### 1.3 项目目标

| 目标 | 说明 | 衡量指标 |
| --- | --- | --- |
| 提效 | 缩短单份合同初审耗时 | 初审时间由小时级降至分钟级 |
| 标准化 | 以可配置规则引擎统一审查口径 | 同类条款风险认定一致率显著提升 |
| 风险可控 | 关键条款强制覆盖检查，支持人工复核兜底 | 关键条款覆盖率 100%，复核留痕完整 |
| 可追溯 | 审查过程、AI 建议与人工处置全程留痕 | 任一审查记录可回放、可审计 |
| 安全可控 | 大模型私有化部署，合同数据不出内网 | 支持离线环境全链路运行 |

### 1.4 名词术语

| 术语 | 说明 |
| --- | --- |
| LLM | 大语言模型，本平台对接私有化部署的 DeepSeek 模型服务 |
| RAG | 检索增强生成，将规则库、历史合同、标准模板检索结果注入提示词以提升准确性 |
| Agent | 具备特定职责的智能体节点，本平台以 LangGraph 编排多个 Agent 协作完成审查 |
| Checkpoint | LangGraph 工作流的状态持久化快照，用于中断恢复与人工复核续跑 |
| 条款 | 合同中的独立条文单元，是风险识别与合规检查的基本粒度 |
| 人机协同 | AI 给出建议，人工决定接受、拒绝或编辑，最终意见以人工确认为准 |

## 2. 用户角色与使用场景

### 2.1 用户角色

| 角色 | 职责描述 | 核心诉求 |
| --- | --- | --- |
| 法务专员 | 合同初审、处理 AI 建议、出具审查意见 | 快速定位风险、减少机械劳动 |
| 法务主管 / 合规负责人 | 复核高风险合同、维护审查规则、查看统计 | 统一审查标准、掌握整体风险态势 |
| 系统管理员 | 账号权限管理、规则库与模板维护、系统运维 | 权限可控、知识库可维护、运行状态可观测 |

### 2.2 典型使用场景

**场景一：常规合同初审**
法务专员上传一份采购合同，系统自动完成文本解析与条款提取，多 Agent 并行执行风险识别与合规检查，产出风险清单与修改建议；专员在审查工作台逐条处理（接受/拒绝/编辑），确认后生成审查报告。

**场景二：高风险条款人工复核**
系统识别出"无限连带责任""单方解约权"等高风险条款时，工作流自动中断并将任务推入人工复核队列，由法务主管处置；复核完成后工作流从中断点恢复，继续生成报告。

**场景三：审查规则维护**
合规负责人将最新监管要求（如数据合规新规）整理为规则文档上传至规则库，经向量化入库后，后续合同审查自动按新规则执行，无需修改代码。

## 3. 业务范围

### 3.1 范围内

- 合同文件上传与文本解析（PDF、Word、TXT）
- 合同条款结构化提取
- 基于规则引擎 + RAG 的风险识别与合规检查
- AI 修改建议生成与版本化管理
- 人工复核队列与人机协同处置
- 审查报告生成与导出
- 规则库、历史合同库、标准模板库的维护与检索
- 用户认证、角色权限（RBAC）与操作审计
- 私有化部署、运行监控与健康检查

### 3.2 范围外

- 合同电子签章与在线签署（对接第三方签署平台，不在本期范围）
- 合同全生命周期管理（履约跟踪、归档销毁等仅预留扩展）
- 法律意见的最终出具（系统提供辅助建议，法律判断由法务人员负责）

## 4. 功能性需求

### 4.1 功能结构总览

| 一级模块 | 二级功能 | 优先级 |
| --- | --- | --- |
| 合同接入 | 合同上传、格式校验、文本解析 | P0 |
| 智能审查 | 条款提取、风险识别、合规检查、修改建议生成 | P0 |
| 人机协同 | 人工复核队列、建议处置（接受/拒绝/编辑）、修订对比 | P0 |
| 审查报告 | 报告生成、报告导出、版本留痕 | P0 |
| 审查工作台 | 任务列表、进度实时展示、风险视图、修订视图 | P0 |
| 规则与知识库 | 规则管理、历史合同管理、标准模板管理、向量检索 | P1 |
| 系统管理 | 用户管理、角色权限、操作审计、系统配置 | P1 |
| 运维支撑 | 健康检查、监控告警、日志收集 | P1 |

### 4.2 合同接入

**FR-01 合同上传**
- 支持 PDF、DOCX、TXT 格式，单文件大小限制可配置（默认 50MB）。
- 支持上传即创建审查任务，返回任务 ID 供进度查询。
- 对无法解析、加密、扫描件（无文本层）文件给出明确错误提示。

**FR-02 文本解析**
- 提取合同全文文本，保留章节层级与段落结构。
- 解析结果持久化，作为后续条款提取的输入。

### 4.3 智能审查

**FR-03 条款提取**
- 将合同文本切分为结构化条款（条款编号、标题、正文、类型）。
- 识别常见条款类型：当事人、标的、价款、履行期限、违约责任、知识产权、保密、争议解决、管辖等。
- 对提取结果置信度低的条款进行标记，交由人工确认。

**FR-04 风险识别**
- 基于规则库 + RAG 检索（规则、历史案例、标准模板）对每个条款进行风险识别。
- 风险分级：高 / 中 / 低；每条风险输出：所在条款、风险类型、风险描述、依据来源（规则编号/模板出处）、置信度。
- 关键条款（违约责任、管辖、知识产权归属、保密、付款）为强制覆盖项，缺失时按高风险处理。

**FR-05 合规检查**
- 依据可配置规则引擎执行合规校验（如必备条款完整性、金额与日期一致性、禁用表述检查）。
- 规则支持启停与版本管理，规则变更只影响后续新任务，不回溯已审合同。

**FR-06 修改建议生成**
- 针对每条确认风险，生成条款级修改建议（建议文本 + 修改理由 + 引用依据）。
- 建议仅作为草稿，必须经人工处置后才生效。

### 4.4 人机协同

**FR-07 人工复核队列**
- 高风险事项自动进入复核队列，支持按风险等级、时间、提交人筛选。
- 复核任务支持认领、退回、批注。

**FR-08 建议处置**
- 对每条 AI 建议支持三种处置：接受、拒绝、编辑后接受。
- 所有处置动作记录操作人、时间与处置前后内容，形成不可篡改的处置日志。

**FR-09 修订对比**
- 提供原文与修订稿的 Diff 对比视图（条款级高亮）。
- 修订历史采用 append-only 版本模型，任一历史版本可回看、不可改写。

### 4.5 审查报告

**FR-10 报告生成**
- 复核完成后自动生成结构化审查报告：合同概要、风险清单（分级统计）、条款级意见、修改对照、复核记录。
- 支持按模板生成，模板可配置。

**FR-11 报告导出**
- 支持 PDF / Word 导出，报告附带审查留痕信息（审查人、复核人、时间线）。

### 4.6 规则与知识库

**FR-12 规则管理**
- 规则的增删改查、启停、分组与版本管理。
- 规则文档上传后自动切片、向量化入库，供审查时检索。

**FR-13 知识库管理**
- 历史合同库与标准模板库的上传、分类、检索与删除。
- 支持按相似度检索（Top-K）验证知识库内容质量。

### 4.7 系统管理

**FR-14 用户与权限**
- 用户登录认证（JWT），角色权限控制（RBAC）。
- 预置角色：法务专员、法务主管、系统管理员；支持角色与菜单/接口权限的配置。

**FR-15 操作审计**
- 登录、上传、复核处置、报告导出、规则变更等关键操作全部记录审计日志。

### 4.8 审查过程实时反馈

**FR-16 进度推送**
- 审查工作流各阶段（解析中、条款提取中、风险识别中、待复核、已完成）通过 WebSocket/SSE 实时推送到前端工作台。
- 任务异常失败时推送失败原因，并支持重新发起。

## 5. 非功能性需求

### 5.1 性能需求

| 编号 | 指标 | 要求 |
| --- | --- | --- |
| NFR-P1 | 单份合同（≤50 页）端到端审查耗时 | ≤ 5 分钟（不含人工复核等待） |
| NFR-P2 | 审查进度推送延迟 | ≤ 2 秒 |
| NFR-P3 | 并发审查任务 | ≥ 10 个任务并行（私有化单节点部署） |
| NFR-P4 | 知识库检索响应 | Top-K 检索 ≤ 500ms |
| NFR-P5 | 常规页面/接口响应 | P95 ≤ 1s（不含模型推理类接口） |

### 5.2 安全需求

| 编号 | 要求 |
| --- | --- |
| NFR-S1 | 大模型与向量库全部私有化部署，支持内网离线运行，合同数据不出企业边界 |
| NFR-S2 | 接口统一鉴权（JWT），敏感接口按 RBAC 权限码控制 |
| NFR-S3 | 传输加密（HTTPS / Nginx 终止 TLS），存储层合同文件与数据库访问受控 |
| NFR-S4 | 全部审查处置动作留痕，审计日志不可篡改、可导出 |
| NFR-S5 | AI 输出不得直接生效，必须经人工确认，防止幻觉内容进入正式文件 |

### 5.3 可靠性与可用性

| 编号 | 要求 |
| --- | --- |
| NFR-R1 | 审查工作流支持断点恢复：服务重启或人工复核等待后，工作流可从最近 checkpoint 恢复，不重复执行已完成节点 |
| NFR-R2 | 单节点 Agent 执行失败可重试，重试失败任务进入失败态并告警，不影响其他任务 |
| NFR-R3 | 多用户任务相互隔离（thread_id 维度），互不串扰 |
| NFR-R4 | 核心服务具备健康检查，异常时可被监控系统发现并告警 |

### 5.4 可维护性与可扩展性

| 编号 | 要求 |
| --- | --- |
| NFR-M1 | 审查规则、提示词、报告模板均可配置，无需改代码即可调整审查口径 |
| NFR-M2 | Agent 节点职责单一、可插拔，新增审查维度（如税务条款专项）以新增节点方式扩展 |
| NFR-M3 | 大模型服务抽象对接，可切换 DeepSeek 及其他私有化模型，上层业务无感知 |
| NFR-M4 | 全组件容器化，支持一键部署与私有化交付 |

### 5.5 兼容性需求

- 前端兼容 Chrome / Edge 主流版本。
- 部署环境支持 Linux 服务器（Docker + Docker Compose）。

## 6. 核心业务流程

### 6.1 合同审查主流程

```
上传合同 → 文本解析 → 条款提取 → 风险识别 ∥ 合规检查（并行）
        → 修改建议生成 → 人工复核（高风险中断）→ 报告生成 → 导出归档
```

1. 法务专员上传合同，系统创建审查任务并进入工作流。
2. 解析节点完成文本抽取；条款提取节点输出结构化条款。
3. 风险识别与合规检查并行执行，各自结合 RAG 检索结果产出风险/不合规项。
4. 修改建议节点汇总问题条款并生成建议稿。
5. 存在高风险项时工作流中断，任务进入人工复核队列；法务主管处置后工作流从断点恢复。
6. 报告节点基于模板生成审查报告，专员确认后导出，任务归档，全程留痕。

### 6.2 规则维护流程

合规负责人上传/编辑规则 → 系统切片并向量化入库 → 规则版本生效 → 后续审查任务自动按新版本执行。

## 7. 数据需求

### 7.1 核心业务数据

| 数据对象 | 说明 |
| --- | --- |
| 合同文件 | 原始上传文件及其解析文本 |
| 条款 | 结构化条款（编号、类型、正文、置信度） |
| 风险项 | 风险等级、类型、描述、依据、置信度、处置状态 |
| 修改建议与修订版本 | 建议文本、处置结果、append-only 修订历史 |
| 审查任务 | 任务状态机、当前节点、中断信息、关联人员 |
| 审查报告 | 报告内容、模板版本、导出记录 |
| 规则/知识库 | 规则条目、历史合同、标准模板及其向量索引 |
| 用户与权限 | 用户、角色、权限码、审计日志 |

### 7.2 数据安全要求

- 合同原文与审查数据仅存储于企业内网；向量库本地化，不调用公网模型接口。
- 数据按租户/部门权限隔离访问；删除操作走软删除并保留审计痕迹。

## 8. 约束与假设

### 8.1 约束

1. 大模型须支持私有化部署（本期对接 DeepSeek），不得依赖公网 API。
2. 部署形态为 Docker Compose 一体化交付，适配企业内网单节点起步。
3. AI 建议不直接修改正式合同文本，最终文本以人工确认版本为准。

### 8.2 假设

1. 输入合同为可提取文本的电子文档（扫描件 OCR 不在本期范围）。
2. 企业可提供基础规则库与历史合同样本用于知识库冷启动。
3. 使用人员具备基本法务知识，能够理解并处置 AI 建议。

## 9. 验收标准

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| AC-01 | 端到端审查流程 | 上传合同后可完成解析→审查→复核→报告全链路，无阻断性缺陷 |
| AC-02 | 关键条款覆盖 | 违约责任、管辖、知识产权等关键条款 100% 被检查，缺失必报高风险 |
| AC-03 | 人机协同 | AI 建议可接受/拒绝/编辑，处置记录完整可查，修订版本可追溯 |
| AC-04 | 中断恢复 | 人工复核中断后工作流可正确恢复，已完成节点不重复执行 |
| AC-05 | 权限控制 | 不同角色仅可访问授权功能与数据，越权访问被拒绝 |
| AC-06 | 私有化部署 | 内网离线环境下系统全链路可用，Docker Compose 一键部署成功 |
| AC-07 | 性能 | 满足第 5.1 节性能指标 |
| AC-08 | 留痕审计 | 任一合同从上传到报告导出的完整操作链可回放 |

## 10. 后续迭代方向（规划）

1. 扫描件 OCR 接入，扩大合同来源覆盖。
2. 与电子签章、合同全生命周期管理系统对接。
3. 基于审查历史数据微调领域模型，进一步提升风险识别准确率。
4. 引入 GraphRAG，构建法规—条款—案例知识图谱，增强复杂合规推理能力。
